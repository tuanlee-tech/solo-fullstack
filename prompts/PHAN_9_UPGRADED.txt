## 9.0.5. NGUYÊN TẮC HỌC SÂU (Áp dụng cho MỌI module)

### A. Spiral Learning — 3 Vòng

```
VÒNG 1: FOUNDATION (Biết nó là gì)
└── Đọc tài liệu gốc, viết code demo, hiểu cơ chế hoạt động

VÒNG 2: APPLICATION (Biết dùng nó trong thực tế)
└── Áp dụng vào project, xử lý edge case, đọc source code thư viện

VÒNG 3: MASTERY (Biết tại sao nó thiết kế như vậy)
└── Re-implement từ đầu, phân tích trade-off, dạy lại người khác,
    simulate incident, review code người khác, viết ADR/RFC
```

### B. Deliberate Practice — 4 hoạt động bắt buộc mỗi tuần

| Hoạt động | Tần suất | Mục đích |
|-----------|----------|----------|
| **Source Code Reading** | 2–3 giờ/tuần | Đọc source Zustand, TanStack Query, Radix, React Fiber, V8 blog |
| **Edge Case Lab** | 1 buổi/tuần | "Điều gì xảy ra nếu...", viết test cho edge case, simulate failure |
| **War Story Documentation** | 1 bài/tuần | Bối cảnh → Ràng buộc → Lựa chọn → Quyết định → Trade-off → Bài học |
| **Teach Back** | 1 buổi/tuần | Giải thích cho junior tưởng tượng hoặc viết blog kỹ thuật |

### C. Milestone đánh giá năng lực

- **Milestone 1:** Debug được 1 bug production thực mà không cần Google
- **Milestone 2:** Review PR của người khác, tìm ra lỗi security/performance họ không thấy

- **Milestone 4:** Tự implement 1 thư viện nhỏ (giống Zustand, Virtual Scroll, hoặc 1 phần React)

**Spiral 3 vòng:**

**Exit Criteria:** Giải thích được vì sao `Promise.then` chạy trước `setTimeout(..., 0)`. Debug được memory leak qua Chrome DevTools Memory tab.

### Module 0.1x — Scheduler & Browser Task Scheduling *(Bổ sung)*

**Kiến thức:**
- `requestAnimationFrame`: sync với display refresh rate (60Hz/120Hz), callback nhận timestamp
- `requestIdleCallback`: chạy task khi main thread rảnh, `timeout` để đảm bảo deadline
- Prioritized Task Scheduling API: `scheduler.postTask()`, `priority: 'user-blocking' | 'user-visible' | 'background'`
- React Scheduler internals: `unstable_scheduleCallback`, expiration time, lane-based priority
- Khi nào dùng cái nào: rAF cho animation, rIC cho non-urgent work, `postTask` cho prioritized queue, React Scheduler cho render priority

**Spiral 3 vòng:**
- **V1:** Viết demo so sánh `setTimeout(0)` vs `requestAnimationFrame` vs `requestIdleCallback`; vẽ timeline
- **V2:** Dùng `scheduler.postTask()` để ưu tiên tải dữ liệu hiển thị trước, analytics sau; đọc source React Scheduler (`packages/scheduler`)
- **V3:** **Edge Case Lab:** `requestIdleCallback` bị delay vĩnh viễn trên trang liên tục busy — fallback bằng `postTask` hoặc rAF; **War Story:** "Animation drop frame vì chạy heavy computation trước rAF"; **Teach Back:** Giải thích React Scheduler priority cho junior

**Exit Criteria:** Giải thích được sự khác biệt giữa rAF, rIC, `postTask`, và React Scheduler. Viết được 1 task queue đơn giản ưu tiên animation > user input > background sync.

### Module 0.2 — Browser Rendering Engine *(Bổ sung ADR + CSS Rendering Deep Dive)*

**Kiến thức:**
- HTML Parser → DOM; CSS Parser → CSSOM; DOM + CSSOM → Render Tree
- Layout (Reflow) vs Paint (Repaint) vs Composite; GPU Layer; `will-change`, `transform` vs `top/left`
- Critical Rendering Path: parser-blocking, render-blocking, CSSOM construction
- Reflow trigger: đọc layout property (`offsetHeight`) sau đó write style → forced synchronous layout (layout thrashing)
- **CSS Rendering Deep Dive:** Stacking Context (z-index, opacity, transform, filter, isolation, contain), Containing Block (position, transform, perspective), Formatting Context (Block Formatting Context — float, overflow, display: flow-root; Inline Formatting Context)

**Spiral 3 vòng:**
- **V1:** Đọc "How Browsers Work" (HTML5 Rocks), vẽ pipeline trên giấy; viết demo tạo BFC bằng `overflow: hidden` vs `display: flow-root`
- **V2:** Profile 1 trang chậm bằng Chrome DevTools Performance tab, tìm forced reflow; debug z-index "không work" do thiếu stacking context
- **V3:** **Edge Case Lab:** `offsetHeight` trong loop gây layout thrashing — fix bằng batch read/write; **Edge Case Lab:** `position: fixed` bị cắt bởi `transform` của ancestor (containing block thay đổi); **War Story:** "Animation lag vì đổi `top/left` thay vì `transform`"; **Teach Back:** Giải thích GPU Layer và Stacking Context cho junior

**Exit Criteria:** Vẽ được Rendering Pipeline từ HTML đến Pixel. Giải thích được tại sao `transform: translate3d` mượt hơn `top: 10px`. Giải thích được tại sao `z-index: 9999` vẫn bị che. Tạo được BFC để clear float đúng cách.

### Module 0.3 — Browser APIs *(Bổ sung Browser Storage Deep Dive)*

**Kiến thức:**
- Fetch, Storage, IndexedDB (Dexie.js), Broadcast Channel, Clipboard, Notification
- `IntersectionObserver`, `ResizeObserver`, `MutationObserver`
- Web Workers, Service Worker, Page Visibility API
- **Browser Storage & Persistence:** Storage Quota (`navigator.storage.estimate()`), Eviction policy (LRU, persistent), Storage Manager API (`persist()`, `persisted()`), `storage` event để sync cross-tab, `navigator.storage.estimate()` để kiểm tra dung lượng còn lại

**Spiral 3 vòng:**
- **V1:** Viết demo từng API, so sánh use case; kiểm tra quota bằng `estimate()`
- **V2:** Dùng `IntersectionObserver` cho lazy load thực tế; Web Workers cho parse CSV; test IndexedDB bị xóa khi hết quota
- **V3:** **Edge Case Lab:** `ResizeObserver` callback trigger liên tục — debounce đúng cách; **Edge Case Lab:** `persist()` bị từ chối trên Safari private mode — graceful fallback; **War Story:** "Broadcast Channel không work cross-origin" — hiểu đúng scope

**Exit Criteria:** So sánh được `localStorage` vs `sessionStorage` vs `IndexedDB` vs `Cookie` — biết khi nào dùng cái nào. Giải thích được storage quota và eviction. Xử lý được lỗi "QuotaExceededError".

### Module 0.6 — HTTP & Networking *(Bổ sung ADR)*

**Kiến thức:**

### Module 0.6x — API Design & Backend Contract *(Bổ sung)*

**Kiến thức:**
- REST maturity model (Level 0–3), resource naming, HTTP method semantics (idempotent vs safe)
- Pagination: offset vs cursor (`created_at` + `id`), pros/cons, deep paging problem
- Filtering, sorting, field selection (`?fields=name,email`), API versioning (URL vs header vs media type)
- Idempotency key: tại sao cần, cách generate (UUID + client seed), retry strategy
- Rate Limit: `429 Too Many Requests`, `Retry-After`, exponential backoff, jitter
- Frontend perspective: consume API đúng cách, handle `409 Conflict`, `412 Precondition Failed`

**Spiral 3 vòng:**
- **V1:** Đọc "API Design Patterns" hoặc Microsoft REST API Guidelines; viết 1 spec API đơn giản cho blog
- **V2:** Implement cursor pagination cho feed; xử lý rate limit với exponential backoff; đọc source Stripe API design
- **V3:** **Edge Case Lab:** User scroll nhanh → gửi 10 request pagination cùng lúc → race condition, hiển thị sai thứ tự; fix bằng request cancellation hoặc sequencing; **War Story:** "Backend đổi API version không báo trước — FE crash vì không validate response shape"

**Exit Criteria:** Thiết kế được API endpoint với cursor pagination và idempotency key. Implement exponential backoff với jitter. Giải thích được tại sao offset pagination không scale.

### Module 0.7 — Debugging Methodology *(Bổ sung)*

**Kiến thức:**
- **RIMHVRP framework:** Reproduce → Isolate → Measure → Hypothesis → Verify → Fix → Postmortem
- Reproduce: tìm minimal steps, check environment, version, data
- Isolate: binary search (git bisect), comment code, swap component, devtools profiler
- Measure: không đoán — dùng Performance tab, Memory tab, Network tab, LoAF API
- Hypothesis: dựa trên data, không dựa trên cảm tính
- Verify: fix phải có test/regression, reproduce lại bug sau fix để confirm
- Postmortem: timeline, impact, root cause (5 Whys), fix, action items, prevention

**Spiral 3 vòng:**
- **V1:** Đọc "How to Report Bugs Effectively" (Simon Tatham); học cách đọc stack trace, source map
- **V2:** Debug 1 bug thực tế áp dụng đủ 7 bước; dùng Chrome DevTools để tìm root cause (không console.log)
- **V3:** **Edge Case Lab:** Bug chỉ reproduce trên production — dùng Sentry breadcrumbs, session replay, log correlation ID để isolate; **War Story:** "Fix bug bằng cách đoán → introduce regression lớn hơn"; **Teach Back:** Hướng dẫn junior debug bằng hypothesis-driven thay vì "thử đại"

**Exit Criteria:** Debug được 1 bug production thực trong 30 phút không cần Google (chỉ dùng devtools + source code). Viết được postmortem đúng format.

### Module 2.4 — Accessibility Engineering *(Bổ sung — Module riêng)*

**Kiến thức:**
- WCAG 2.1/2.2 AA: Perceivable, Operable, Understandable, Robust — 78 success criteria thường gặp
- Semantic HTML: landmark regions (`<main>`, `<nav>`, `<aside>`), heading hierarchy, `<button>` vs `<a>`, form labels
- ARIA: khi nào cần (không dùng nếu semantic HTML đủ), `role`, `aria-*` states/properties, `aria-live` regions
- Keyboard Navigation: `tabindex` strategy (roving tabindex), focus trap, focus visible, skip links, logical tab order
- Screen Reader: NVDA (Windows), VoiceOver (macOS/iOS), TalkBack (Android) — test flow chính bằng screen reader thật
- Color & Contrast: WCAG AA 4.5:1 normal text, 3:1 large text/UI components, không dùng color alone để truyền thông tin
- Motion: `prefers-reduced-motion`, `prefers-contrast`, `prefers-color-scheme`
- Tools: axe DevTools, Lighthouse a11y audit, `jest-axe`, WAVE, pa11y

**Spiral 3 vòng:**
- **V1:** Audit landing page bằng axe DevTools, fix tất cả critical/serious issues; viết semantic HTML đúng cho blog

**Spiral 3 vòng:**
- **V1:** Đọc 6 war stories, hiểu format: Bối cảnh → Ràng buộc → Lựa chọn → Quyết định → Trade-off → Bài học
- **V2:** Simulate 1–2 tình huống với project của mình (ví dụ: giả lập incident 2 giờ sáng bằng cách tạo bug production trên staging)
- **V3:** **Teach Back:** Viết blog/vlog về 1 tình huống, nhận feedback từ cộng đồng

**Exit Criteria:** Kể được 2–3 war stories theo format STAR/Bối cảnh → Quyết định → Trade-off → Bài học. Không defensive khi kể.

---

### Module 7.8 — RADIO Practice #4

**Đề gợi ý:** Thiết kế Migration Strategy hoặc E-commerce Checkout với graceful degradation + offline support.

**Spiral 3 vòng:**
- **V1:** Luyện đề, record bản thân, tự chấm điểm
- **V2:** Mock interview với người phản biện
- **V3:** Nhận feedback, iterate cách trình bày trade-off

**Exit Criteria:** Hoàn thành đề trong 45 phút, đề cập rollback strategy, feature flag, và monitoring.

**Deliverable Stage 7:** Project 6 hoàn chỉnh — demo song song jQuery + React trên cùng 1 domain, 1–2 page migrated, rollback drill thực hiện, war stories documented.

## STAGE 8 — TỔNG HỢP & SẴN SÀNG PHỎNG VẤN (Không có project mới)

> Đây không phải "học thêm" — đây là consolidation. Nếu Stage 0–7 đã làm đúng Exit Criteria, Stage 8 chỉ là ôn và luyện phản xạ.  
> **Nhắc nhở:** Sau Stage 8, quay lại Stage 0 với góc nhìn mới — đó là **Core Loop**.

---

### Module 8.1 — Portfolio Site

**Kiến thức:**
- Tổng hợp 6 project: README chi tiết (setup, architecture, decisions, trade-offs), demo link, tech stack
- Video demo 2–3 phút mỗi project: nói về problem, solution, trade-off, kết quả đo được (performance, accessibility, conversion)
- GitHub profile optimized: pinned repos, bio rõ ràng, contribution graph active, open source contribution nếu có

**Spiral 3 vòng:**
- **V1:** Xây portfolio site tổng hợp bằng Next.js
- **V2:** Quay video demo, viết README chi tiết cho từng repo
- **V3:** **Edge Case Lab:** Portfolio site chính cũng phải pass Lighthouse CI, a11y audit, có ADR cho chính quyết định kiến trúc của nó

**Exit Criteria:** Portfolio site live, có video demo, GitHub profile optimized.

---

### Module 8.2 — RADIO Mock Interview Cường Độ Cao

**Kiến thức:**
- Mock full 45 phút có người phản biện (hoặc AI đóng vai interviewer)
- Checklist tự chấm điểm: hỏi requirements (5 phút), RADIO framework đúng, nói to suy nghĩ, đề cập trade-offs, đề cập graceful degradation, đề cập accessibility, đề cập security, đề cập monitoring

**Spiral 3 vòng:**
- **V1:** Luyện 3 đề/tuần, record bản thân, tự chấm điểm theo checklist
- **V2:** Mock interview với bạn bè/mentor/AI — nhận feedback về cách trình bày, tốc độ nói, độ rõ ràng
- **V3:** **Edge Case Lab:** Interviewer hỏi ngược: "Tại sao không dùng micro-frontend?" / "Nếu traffic tăng 10x thì sao?" / "Nếu API này fail nhưng API kia vẫn chạy?" — luyện trả lời không defensive, dựa trên data

**Exit Criteria:** Hoàn thành ít nhất 10 mock interview full 45 phút, có recording để xem lại tiến bộ. Không nhảy vào giải pháp trong 5 phút đầu.

---

### Module 8.3 — Live Coding Practice

**Kiến thức:**
- Modal từ đầu: focus trap, Escape to close, scroll lock, ARIA, animation
- Dropdown/Select: keyboard navigation (↑↓, Enter, Escape), `aria-expanded`, positioning (không bị cut bởi `overflow: hidden`)
- Data Table: sort, filter, pagination, row selection, virtual scroll
- Optimize React component: dùng Profiler tìm unnecessary render, apply memoization đúng cách
- Debug TypeScript error: đọc error message, fix không dùng `as` hoặc `@ts-ignore`

**Spiral 3 vòng:**
- **V1:** Live code 1 component/tuần trong 30–45 phút, không nhìn tài liệu
- **V2:** Thêm yêu cầu "thay đổi" giữa chừng (interviewer bảo "giờ thêm feature X") — luyện adapt
- **V3:** **Edge Case Lab:** Live code xong, interviewer hỏi: "Còn cách nào khác không? Trade-off là gì?" — luyện trả lời dạng "Tôi chọn X vì Y, nhưng nếu Z tôi sẽ cân nhắc W"

**Exit Criteria:** Live code được Modal, Dropdown, Data Table trong 30–45 phút không nhìn tài liệu. Giải thích được trade-off của từng quyết định.

---

### Module 8.4 — Ôn Tập Tổng Hợp Security + Testing + Observability

**Kiến thức:**
- Security: XSS, CSRF, CSP, CORS, Auth, SOP, `iframe sandbox`, COOP/COEP/CORP, Trusted Types, supply chain
- Testing: Unit, Integration, E2E, MSW, visual regression, `jest-axe`
- Observability: Logs, Metrics, Traces, RUM, Session Replay, Alerting, OpenTelemetry

**Spiral 3 vòng:**
- **V1:** Làm 1 bài audit security cho chính portfolio site; làm 1 bài audit test coverage
- **V2:** Tìm lỗ hổng còn sót trong project cũ, viết test còn thiếu
- **V3:** **Edge Case Lab:** Simulate 1 bug security production — viết incident report đầy đủ (timeline, impact, root cause, fix, prevention)

**Exit Criteria:** Tự audit được security và testing cho 1 project bất kỳ, tìm ra điểm yếu chưa phát hiện trước đó.

---

### Module 8.5 — Behavioral & Đàm Phán Lương

**Kiến thức:**
- STAR format: Situation, Task, Action, Result (kết quả đo được nếu có)
- Chuẩn bị 5 câu chuyện thật: bug khó, bất đồng kỹ thuật, deadline gấp, mentor junior, incident
- War Stories: 6 tình huống thực chiến đã luyện ở Stage 7
- Đàm phán offer: base, equity, benefit, level — không chỉ nhận offer đầu tiên; biết "walk away" khi nào

**Spiral 3 vòng:**
- **V1:** Viết script STAR cho 7 câu hỏi phổ biến, luyện nói trước gương
- **V2:** Mock behavioral interview với bạn bè, nhận feedback về sự tự tin và độ cụ thể
- **V3:** **Edge Case Lab:** Interviewer hỏi: "Bạn có điểm yếu gì?" / "Tại sao bạn rời công ty cũ?" / "Mức lương mong muốn?" — luyện trả lời thật nhưng professional, không defensive, không khai báo số quá sớm

**Exit Criteria:** Kể được 3–4 câu chuyện theo STAR trong 2 phút mỗi câu. Biết cách đàm phán base salary và equity. Có "walk away" number.

---

### Module 8.6 — Apply & Iterate

**Kiến thức:**
- CV optimized cho Senior FE: highlight project, metrics (performance improve X%, bug reduce Y%, test coverage Z%), không liệt kê công nghệ
- Cover letter template: startup (move fast, ownership) vs enterprise (scale, process, mentorship)
- Theo dõi application: Notion/Airtable, ghi lại công ty, vòng phỏng vấn, feedback, iterate
- Follow up sau 1 tuần nếu không phản hồi

**Spiral 3 vòng:**
- **V1:** Apply 10+ job trong 1 tuần đầu tiên, ghi lại phản hồi
- **V2:** Nếu không pass vòng CV — iterate CV. Nếu fail vòng live code — luyện lại Module 8.3. Nếu fail vòng System Design — luyện lại Module 8.2. Nếu fail vòng behavioral — luyện lại Module 8.5.
- **V3:** **Edge Case Lab:** Nhận reject — phân tích nguyên nhân (không phải lúc nào cũng là "họ không hiểu giá trị của tôi"), điều chỉnh và apply tiếp

**Exit Criteria:** Apply liên tục, iterate dựa trên feedback thực tế. Không giới hạn số lượng — đến khi có offer phù hợp.

## KẾT THÚC PHẦN 9 (UPGRADED)

> **"Không hời hợt, nghiên cứu sâu."**
>
> Với mindset này, bạn không còn "học để pass phỏng vấn" — bạn **học để trở thành người mà người khác tìm đến khi production gặp vấn đề**. Đó là định nghĩa của Senior 5+.
>
> Lộ trình này không có ngày kết thúc. Sau Stage 8, bạn quay lại Stage 0 với góc nhìn mới — đọc lại "You Don't Know JS" và thấy mình hiểu sâu hơn lần trước. Đọc lại V8 blog và thấy mình nắm được context. Đó là **Spiral Learning**: mỗi vòng xoắn ốc đưa bạn lên cao hơn, nhìn rộng hơn, nhưng vẫn đi trên chính nền tảng đã xây.
>
> **Quy tắc cuối cùng:** Không sang module sau khi chưa đạt Exit Criteria. Không học vội để "kịp timeline". Không so sánh với người khác. Chỉ so sánh với chính mình 3 tháng trước.
>
> **Mỗi checkbox trong checklist là một kiến thức bạn PHẢI giải thích được cho người khác. Nếu không giải thích được, chưa hiểu sâu — quay lại học.**
>
> **Học xong Khối 1 này, bạn không chỉ "sẵn sàng phỏng vấn Senior". Bạn đã xây được nền móng để học Khối 2 (Backend & Ecosystem) và Khối 3 (DevOps) một cách tự nhiên — vì bạn hiểu cả máy tính, trình duyệt, network, framework, lẫn cách một sản phẩm thực sự được xây dựng và vận hành.**
>
> **Phiên bản này đã tích hợp:** Core Loop vĩnh cửu, Scheduler, CSS Rendering Deep Dive, Browser Storage & Persistence, Web Components & Shadow DOM, API Design & Backend Contract, Debugging Methodology, Accessibility Engineering (module riêng), Caching Patterns & Invalidation, Feature Flags Nâng Cao (Dark Launch, Progressive Rollout), OpenTelemetry & Distributed Tracing, Shadow DOM trong Design System.
