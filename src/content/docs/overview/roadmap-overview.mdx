## 0. Vấn đề thực tế

<Aside type="danger" title="Câu hỏi đau đầu của mid-level">
  "Học fullstack để đi làm lên Staff, hay để tự kinh doanh? Và nếu chọn sai thì phải làm lại từ đầu?"
</Aside>


## 1. Tại sao tách lõi chung và rẽ nhánh

Hai con đường cần kỹ năng khác nhau ở giai đoạn nâng cao:

- <strong>Nhánh A (Staff/Architect):</strong> Kafka, service mesh, distributed systems
- <strong>Nhánh B (Solo Founder):</strong> Sales, validate ý tưởng, unit economics

Học cả hai cùng lúc kéo bạn về hai ưu tiên đối nghịch. Giải pháp:

<Steps>
  <ol>
    <li><strong>Học lõi chung trước</strong> — thứ cả hai con đường đều cần 100%</li>
    <li><strong>Dừng lại ở điểm rẽ nhánh</strong> — đánh giá hoàn cảnh thật lúc đó</li>
    <li><strong>Chọn Nhánh A hoặc B</strong> — có thể đổi nhánh sau này nếu hoàn cảnh thay đổi</li>
  </ol>
</Steps>

## 2. Lõi chung — 3 khối bắt buộc

Mỗi khối không chỉ là checklist kiến thức, mà là <strong>năng lực chứng minh được</strong>.

    <li>Auth: JWT (Access/Refresh), OAuth2/OIDC, RBAC/ABAC, Session Management</li>
    <li>Security: OWASP Top 10, XSS, CSRF, Rate Limiting, Argon2/Bcrypt</li>
    <li>Webhooks: Verify signature, Retry with backoff, Idempotency keys</li>
    <li>File Upload: Validation, virus scan, signed URL, CDN upload</li>

    <li>Search: Elasticsearch / Meilisearch (Full-text search, typo-tolerant)</li>
    <li>Email: Transactional (Resend/Postmark), Templates, Deliverability</li>
    <li>Background Jobs: BullMQ + Redis (queue, schedule, retry, dead letter)</li>
    <li>Real-time: WebSockets (Socket.io), Server-Sent Events (SSE)</li>
    <li>API Design: Idempotency, Rate Limiting, Throttling, Circuit Breaker</li>
    <li>OpenAPI / Swagger: Auto-generated docs, client SDK generation</li>
    <li>Event-Driven: Outbox Pattern, Saga Pattern (distributed transactions)</li>
    <li>Tích hợp LLM API (Anthropic/OpenAI SDK), streaming, prompt engineering</li>
    <li>RAG cơ bản + Vector DB (pgvector trên Postgres, chưa cần Pinecone)</li>
    <li>AI Evaluation: kiểm thử & đánh giá chất lượng output AI</li>
    <li>Multi-tenancy: Schema-based vs Row-based (cơ bản)</li>
    <li>Backend/API System Design: rate limiter, webhook idempotency, job queue chịu tải, notification system — luyện dạng bị hỏi ngược trade-off</li>

### 2.3. Khối 3: DevOps cơ bản

## 7. Stack đề xuất (2026)

<Aside type="tip" title="Nguyên tắc stack">
  Dùng SaaS cho non-core, tự build cho core business. Không reinvent the wheel.
</Aside>

| Layer | Công nghệ | Ghi chú |
|---|---|---|
| **Frontend** | Next.js 14+ (App Router) + Tailwind + shadcn/ui | RSC, SEO built-in, Vercel deploy |
| **State FE** | TanStack Query + Zustand | Server state + Client state separation |
| **Backend** | Next.js API Routes (bắt đầu) → NestJS (scale) | Cùng JS/TS ecosystem, chuyển dễ dàng |
| **Database** | PostgreSQL (Neon / Supabase / RDS) | Relational, ACID, Prisma hỗ trợ tốt |
| **AI / LLM** | Anthropic/OpenAI API + pgvector | RAG cơ bản trên chính Postgres |
| **AI Coding Tool** | Claude Code / Cursor / Copilot agent mode | Công cụ hằng ngày, VERIFY output |
| **Cache** | Redis (Upstash / Railway / self-host) | Session, rate limit, BullMQ, cache layer |
| **Auth** | Clerk / NextAuth.js / Supabase Auth | Không tự build auth cho startup sớm |
| **Payment** | Stripe | Checkout, Subscription, Webhooks, Idempotency |
| **Search** | Meilisearch → Elasticsearch (scale, Nhánh A) | Full-text search, typo-tolerant |
| **File Storage** | AWS S3 / Cloudflare R2 | Ảnh, video, documents |
| **Email** | Resend / Postmark | Transactional email, templates |
| **Monitoring** | Sentry + OpenTelemetry basics | FE + BE errors, structured logging, tracing |
| **Analytics** | PostHog / Plausible | Product analytics, funnel, retention |
| **Deploy** | Vercel (FE) → Railway/Render (BE) → AWS/K8s (Nhánh A scale) | Tiến hóa theo traffic |
| **CI/CD** | GitHub Actions | Lint, Test, Build, Deploy tự động, AI security scan |
| **Domain** | Cloudflare | DNS, SSL, CDN, DDoS protection |
| **Git** | pnpm + GitHub | Workspace, lockfile, branch protection, semantic release |

## 10. Cam kết & kỷ luật

<Steps>
  <ol>
    <li><strong>Học mỗi ngày ít nhất 2 giờ</strong> — sáng 1h trước khi đi làm, tối 1h sau khi về</li>
    <li><strong>Cuối tuần làm project</strong> — 4–8 giờ, đóng gói kiến thức tuần đó thành code</li>
    <li><strong>Không xem tutorial passive</strong> — Pause, code theo, sau đó tự làm lại không nhìn</li>
    <li><strong>Mỗi tháng 1 project nhỏ</strong> — Hoàn chỉnh, deploy, share lên GitHub</li>
    <li><strong>Tham gia cộng đồng</strong> — Discord/Reddit dev communities, contribute open source</li>
    <li><strong>Checkpoint 3 tháng/lần</strong> — Đánh giá lại tiến độ và hoàn cảnh, điều chỉnh kế hoạch</li>
    <li><strong>Giữ nhịp bền vững, không burnout</strong> — "2 giờ/ngày đều đặn trong 12 tháng" tốt hơn "6 giờ/ngày trong 2 tháng rồi bỏ cuộc"</li>
    <li><strong>Nhánh A:</strong> Technical blog post định kỳ — củng cố kiến thức + xây thương hiệu cá nhân</li>
    <li><strong>Nhánh B:</strong> "Build in Public" — chia sẻ journey, nhận feedback, tạo accountability</li>
  </ol>
</Steps>

<Aside type="danger" title="Burnout là yếu tố thất bại lớn nhất">
  Dữ liệu khảo sát solo founder gần đây cho thấy <strong>burnout (không phải chiến lược sai)</strong> là yếu tố dự báo thất bại lớn nhất. Nếu cảm thấy kiệt sức liên tục, đó là tín hiệu để <strong>giảm nhịp</strong>, không phải để cố ép thêm.
</Aside>

### Self-check (3 câu hỏi)

<Tabs>
  <TabItem label="Câu 1">
    <p><strong>"Tại sao không học cả Nhánh A và Nhánh B cùng lúc?"</strong></p>
    <p>Hai con đường cần kỹ năng khác nhau ở giai đoạn nâng cao. Học cả hai kéo bạn về hai ưu tiên đối nghịch → kiệt sức mà không đạt được gì.</p>
  </TabItem>
  <TabItem label="Câu 2">
    <p><strong>"Khi nào mới quyết định chọn nhánh?"</strong></p>
    <p>Sau khi hoàn thành 3 khối lõi chung (~tháng 9–12), dựa trên hoàn cảnh thực tế lúc đó — tài chính, ý tưởng, offer việc làm, ràng buộc cá nhân.</p>
  </TabItem>
  <TabItem label="Câu 3">
    <p><strong>"Tại sao học theo chiều ngang thay vì chiều dọc?"</strong></p>

  </TabItem>
